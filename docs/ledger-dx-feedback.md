# Feedback on the Ledger documentation and SDKs

Ledger weighs developer-experience feedback "as much as the code". This log is kept as we work (see section 7.6 of `FIANSO-SPEC.md`). One line when it happens, cleaned up later. `Minutes lost` is honest: `n/a` when we found something while reading and lost no time.

## Time-savers for the next integrator (top of the document, filled at the end)

From the log below, the five that would have saved us the most:

1. **ML-DSA is not in the OS crypto library of the Stax** (it is in `lib_cxng/src`, not in `cx.export`): an app compiles the SDK sources itself, and the RAM budget is tight (about 31 KB of `.bss` on 36 KB of SRAM that also holds the stack). `HAVE_MLDSA_OPTIMIZATION` selects the _low-RAM_ variant, not a faster one.
2. **Clear-signing a new transaction type touches about eight places** in app-xrp (type table, support check, name, field table, both flag functions, `MAX_ARRAY_LEN`, the final parser pass); a missed one silently falls back to blind signing, "Unknown", or clear-signs something it should not.
3. **The app prepends the signing prefix (`STX\0`) itself**; the Device Management Kit forwards the bytes unchanged. Neither page says so, and a client that adds the prefix gets a signature over the wrong bytes.
4. **Loading from macOS**: Docker Desktop does not pass USB to a container, so use `python -m ledgerblue.loadApp`; a locked device answers `0x5515`, an app left open instead of the dashboard `0x6d00`; side-loading an app named `XRP` deletes the store version first.
5. **`PATH_SLIP21_APP_LOAD_PARAMS` is defined in `Makefile.app_params`**, not where an app Makefile reader looks, and the deterministic ML-DSA key generation is in an internal header only.

For the XRPL side (the public nodes): a browser cannot POST JSON to the AlphaNet RPC (the CORS preflight answers 400; use `text/plain`), `account_tx` with `forward` is refused with HTTP 403 by its proxy, and `account_objects` / `account_tx` read the validated ledger, so a freshly funded account is not there yet.

## Overall experience (filled at the end)

54 entries, about 468 minutes lost over the 39 where we measured it (many findings were made while reading and cost nothing, marked `n/a`). The recurring pattern is not missing features but **unstated facts**: which ledger a method reads, who adds the signing prefix, what a build flag really selects, which of several files defines a parameter. The Ledger side was the harder one to learn from documentation alone: the information we needed was in SDK sources, headers and other apps, rarely on a documentation page.
