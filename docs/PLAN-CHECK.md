## 2. Findings that refine the plan

1. **P5 is in the code as the spec describes.** `base64urlDecode` returns a `std::string` (`rippled/include/xrpl/basics/base64.h:88-89`); `verifyPasskeySignature` compares its `char`s with the bytes of a `Slice` through `std::equal` (`rippled/src/libxrpl/protocol/STTx.cpp:478-481`), and `Slice::data()` is `std::uint8_t const*` (`rippled/include/xrpl/basics/Slice.h:30`, `rippled/include/xrpl/basics/Slice.h:88`). On this machine (Apple clang, arm64) `char` is signed: `__CHAR_UNSIGNED__` is not defined. The signed data always holds the `0xF6` prefix of a P-256 `SigningPubKey` (`rippled/include/xrpl/protocol/detail/sfields.macro:346` is a signing field; `rippled/src/libxrpl/protocol/PublicKey.cpp:252-253`). N1's test, run before any change, refused a valid WebAuthn signature (**SIMULATED**: a software WebAuthn authenticator; command and output in `docs/DEVLOG.md`, "Plan check, spike K5 and review gate 1").
2. **A P5 fix must be safe at its activation, in both directions.** Signature verdicts are cached per transaction ID: in two slots of `checkValidity` (`rippled/src/libxrpl/tx/apply.cpp:29-30`, written at `rippled/src/libxrpl/tx/apply.cpp:108` and `rippled/src/libxrpl/tx/apply.cpp:111`), and by the public `BAD` flag, which three places set: after a bad signature in `PeerImp` (`rippled/src/xrpld/overlay/detail/PeerImp.cpp:3150-3155`) and in `NetworkOPs` (`rippled/src/xrpld/app/misc/NetworkOPs.cpp:1484-1489`), and after a malformed result (`rippled/src/xrpld/app/misc/NetworkOPs.cpp:1731-1735`). Upstream met the same problem for `fixCleanup3_4_0` with era-scoped slots and guards (`rippled/src/libxrpl/tx/apply.cpp:34-57`, `rippled/src/libxrpl/tx/apply.cpp:77-95`) and insists that both directions matter (`rippled/src/libxrpl/tx/apply.cpp:83-86`): relay (`rippled/src/xrpld/overlay/detail/PeerImp.cpp:3132-3134`) and `NetworkOPs::submitTransaction` (`rippled/src/xrpld/app/misc/NetworkOPs.cpp:1407-1408`) check against the validated rules, which lag the open-ledger rules used by `preflight2` and the `submit` RPC (`rippled/src/xrpld/rpc/handlers/transaction/Submit.cpp:105-106`). **We choose a simpler rule than era-scoped slots:** while `fixPasskeyChallenge` is disabled, a transaction signed through WebAuthn, that is, with a P-256 `SigningPubKey` and `sfPasskeySignature` (the branch the fix changes, `rippled/src/libxrpl/protocol/STTx.cpp:515`), bypasses the signature slots of `checkValidity`: it is verified on every call and no verdict is read or recorded. None of the three places marks it `BAD`; each guard tests the same rules as the `checkValidity` call beside it, and the guard after a malformed result is defensive, since `preProcessTransaction` refuses first under the same open-ledger rules (`rippled/src/xrpld/app/misc/NetworkOPs.cpp:1472-1473`). A pre-fix verdict is never kept across the activation, and a post-fix verdict is never read by a pre-fix call. The condition is fixed for a transaction ID: `SigningPubKey` is a signed field (`rippled/include/xrpl/protocol/detail/sfields.macro:346`) and `sfPasskeySignature`, `kNotSigning` (`rippled/include/xrpl/protocol/detail/sfields.macro:549`), is still part of the ID, the argument of `rippled/src/libxrpl/tx/apply.cpp:88-91`. It exists only at the top level (`rippled/src/libxrpl/protocol/TxFormats.cpp:33`; the `Signer`, `BatchSigner`, `CounterpartySignature` and `SponsorSignature` formats have no such field: `rippled/src/libxrpl/protocol/InnerObjectFormats.cpp:21-27`, `rippled/src/libxrpl/protocol/InnerObjectFormats.cpp:142-147`, `rippled/src/libxrpl/protocol/InnerObjectFormats.cpp:172-186`). **Forced verdicts stay honoured.** A verdict forced by `forceValidity` (`rippled/src/libxrpl/tx/apply.cpp:140-171`) means the caller verified nothing and wants it trusted in every era (`rippled/src/test/app/tx/apply_test.cpp:40-44`): a cluster relay (`rippled/src/xrpld/overlay/detail/PeerImp.cpp:3160-3163`), ledger replay (`rippled/src/xrpld/app/main/Application.cpp:2071`) and signature checks turned off (`rippled/src/xrpld/rpc/handlers/transaction/Submit.cpp:100-104`, `rippled/src/test/jtx/Env.h:604-608`). The bypass alone would ignore it, and ledger replay would stop reproducing a pre-fix ledger that holds a WebAuthn transaction. So `forceValidity` also sets one more private router flag, on a bit `HashRouterFlags` leaves unassigned (`0x0020`, `rippled/include/xrpl/core/HashRouter.h:20-41`), and the bypass does not apply to a transaction that carries it. **Cost**, until the amendment is enabled: one WebAuthn verification per `checkValidity` call for such a transaction, that is, on every `preflight2` (`rippled/src/libxrpl/tx/Transactor.cpp:337`), on the `submit` RPC, in `preProcessTransaction`, in `submitTransaction` and on relay; the router keeps the entry while it is used (`rippled/src/libxrpl/core/HashRouter.cpp:18-26`), and a peer that sends a bad one is still charged (`rippled/src/xrpld/overlay/detail/PeerImp.cpp:3156`). **Inherit the rule without a change:** the `submit` and `sign` RPCs, which call `checkValidity` (`rippled/src/xrpld/rpc/handlers/transaction/Submit.cpp:100-113`, `rippled/src/xrpld/rpc/detail/TransactionSign.cpp:742-751`); `NetworkOPs::submitTransaction`, reached from consensus (`rippled/src/xrpld/app/ledger/ConsensusTransSetSF.cpp:62`), and the relay duplicate check, which read `BAD` (`rippled/src/xrpld/app/misc/NetworkOPs.cpp:1399`, `rippled/src/xrpld/overlay/detail/PeerImp.cpp:1364`); the queue, which runs `preflight` again when the rules change (`rippled/src/xrpld/app/misc/detail/TxQ.cpp:333-339`); Batch inner transactions, never verified (`rippled/src/libxrpl/tx/Transactor.cpp:326-333`). The local-check slots (`rippled/src/libxrpl/tx/apply.cpp:115-136`) do not depend on the fix and stay cached. **Gating by an amendment** is required: signatures are checked while ledgers are built (`rippled/src/libxrpl/tx/Transactor.cpp:337`; `rippled/CONTRIBUTING.md:77-78`). A dedicated `fixPasskeyChallenge` is preferred to folding the change into `fixCleanup3_5_0` (`rippled/include/xrpl/protocol/detail/features.macro:150`), which has its own scope.
