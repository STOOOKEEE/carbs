## 2. Findings that refine the plan

1. **P5 is in the code as the spec describes.** `base64urlDecode` returns a `std::string` (`rippled/include/xrpl/basics/base64.h:88-89`); `verifyPasskeySignature` compares its `char`s with the bytes of a `Slice` through `std::equal` (`rippled/src/libxrpl/protocol/STTx.cpp:478-481`), and `Slice::data()` is `std::uint8_t const*` (`rippled/include/xrpl/basics/Slice.h:30`, `:88`). On this machine (Apple clang, arm64) `char` is signed: `__CHAR_UNSIGNED__` is not defined. The signed data always holds the `0xF6` prefix of a P-256 `SigningPubKey` (`rippled/src/libxrpl/protocol/PublicKey.cpp:252-253`). The test of N1 decides; the reading alone proves nothing.
2. **A P5 fix must be safe at its activation.** Signature verdicts are cached per transaction ID: two private HashRouter slots in `checkValidity` (`rippled/src/libxrpl/tx/apply.cpp:29-30`, set at `:108` and `:111`) and the public `BAD` flag set by peers and by `NetworkOPs` (`rippled/src/xrpld/overlay/detail/PeerImp.cpp:3138-3155`, `rippled/src/xrpld/app/misc/NetworkOPs.cpp:1476-1490`). Upstream solved the same problem for `fixCleanup3_4_0` with era-scoped slots (`rippled/src/libxrpl/tx/apply.cpp:34-57`, `:77-95`) and guards on `BAD`. No private HashRouter flag is free (`rippled/include/xrpl/core/HashRouter.h:28-40`; `PRIVATE5` and `PRIVATE6` belong to `rippled/src/libxrpl/tx/transactors/escrow/EscrowFinish.cpp:37-38`). The fix therefore records no bad verdict for a transaction that carries `sfPasskeySignature` while the fix is disabled. Good verdicts may be kept, because the old comparison accepts only byte-equal challenges, which the new comparison accepts too. `sfPasskeySignature` exists only at the top level of a transaction (`rippled/src/libxrpl/protocol/TxFormats.cpp:33`; the `Signer`, `BatchSigner`, `CounterpartySignature` and `SponsorSignature` objects have no such field, `rippled/src/libxrpl/protocol/InnerObjectFormats.cpp:21-27`, `:142-147`, `:172-186`), so `tx.isFieldPresent(sfPasskeySignature)` is the whole condition. This goes beyond the N1 text of the plan, which names the comparison and the fix amendment only; it is recorded in `docs/DEVLOG.md` with the fix.
3. **RPC changes need an `API-CHANGELOG.md` entry.** `rippled/src/xrpld/rpc/AGENTS.md` asks for one under `## Unreleased` for any public RPC change; the imported `rippled/API-CHANGELOG.md` has no such section yet (its first release heading is at `:25`). N2 creates it for the `signing_session` type of `ledger_entry` and `account_objects`.
4. **The `jss` names come from the macro.** `JSS(name)` and `JSS(rpcName)` are generated from `ledger_entries.macro` (`rippled/include/xrpl/protocol/jss.h:738-745`), and `account_objects` builds its type table from the same macro (`rippled/src/xrpld/rpc/detail/RPCHelpers.cpp:355-366`). Only `parseSigningSession` is written by hand, picked up by name (`rippled/src/xrpld/rpc/handlers/ledger/LedgerEntry.cpp:1140`).
5. **New amendments go at the top.** `features.macro` asks for it (`rippled/include/xrpl/protocol/detail/features.macro:15-16`, the rule of `rippled/src/libxrpl/tx/AGENTS.md`), although the alphanet composition appended its own features at the bottom (`:145-165`).
6. **The delegable counter already fails, and ours must not move it.** `Delegate_test` counts the `Delegable` types of `transactions.macro` and pins 60 (`rippled/src/test/app/Delegate_test.cpp:2810-2815`, `:2846-2855`); the imported tree has 71, so the upstream `Delegate` suite fails this one test before any change (N0), as the spec noted for the Transia base. Both session types are `NotDelegable`, the count stays 71, and the upstream test is left as it is. The spec's "upstream suites green before and after" therefore reads "no new failure" for `Delegate`. The amendment tests compare totals, not a fixed count (`rippled/src/test/rpc/Feature_test.cpp:95-96`).
7. **jtx, not gtest, for the protocol suites.** `rippled/AGENTS.md` prefers gtest under `src/tests/`. The cases go through the `submit` RPC (`rippled/src/test/jtx/impl/Env.cpp:414-438`), the signature cache, `preflight`, `preclaim` and `Transactor::operator()`, which need an `Application`; the gtest suites under `src/tests/libxrpl` have none. New test files are picked up without a CMake change (`rippled/cmake/XrplCore.cmake:293-297`).
8. **Base failures exist before any change.** The gtest binary fails one test on the imported tree; the full results are in `docs/DEVLOG.md` (task N0).
