### N1 fix (P5) and the passkey wallet proof of concept

- **`fixPasskeyChallenge`** (`XRPL_FIX`, `Supported::Yes`, `DefaultNo`, at the top of `features.macro`). With it, `verifyPasskeySignature` compares the decoded WebAuthn challenge with the signing data as two `Slice`s; without it the old `char` / `uint8_t` comparison stays. The rule is passed as a `bool` from `STTx::checkSign(Rules const&, ...)` through the single-, multi- and batch-signing helpers (`checkBatchSign` now takes the rules). `API-CHANGELOG.md` has an `Unreleased` entry.
- Tests (`PasskeyWebAuthn`, software authenticator, **SIMULATED**): the four refusals of #12, a valid assertion accepted with the fix (its signing data holds a byte ≥ `0x80`), and the same assertion without the fix refused where `char` is signed, accepted where unsigned (the unsigned branch is **UNVERIFIED**: this Mac has a signed `char`). `PasskeyWebAuthn` 3 cases 0 failures; `PasskeyListSet`, `PassKey`, `Batch`, `Feature`, `STTx`, `MultiSign`, `Apply`, `ServerDefinitions` 0 failures (Debug, macOS arm64).
